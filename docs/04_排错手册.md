# 04 · 排错手册（现象 → 原因 → 验证 → 修）

> **怎么用**：先在下面的「急救索引」里找到你的现象，跳到对应小节。每一节都按同一个顺序写：
> **现象 → 最可能原因（按概率排序）→ 怎么验证 → 怎么修**。
>
> 三个前提（不满足的话，下面所有排查都是白费）：
> 1. 你插的是 **UART 口**那颗 Type-C（不是 USB 口）；
> 2. Arduino IDE 里 `USB CDC On Boot = Disabled`、端口选带 COM 的那个；
> 3. 串口监视器波特率 **115200**（少数 sketch 用其它值，文件头会写）。
>
> 不会读串口？→ 先看 [docs/02_环境搭建.md](02_环境搭建.md) 的「串口监视器」一节。

## A. 编译 / 上传（最常见的 8 个红字）

### A1. 编译报错：`pinmap.h: No such file`

**现象**
```
fatal error: pinmap.h: No such file or directory
 #include "pinmap.h"
          ^~~~~~~~~~~
compilation terminated.
```

**最可能原因**：Arduino 只编译 **当前 sketch 文件夹里的文件**，它不会去 `firmware/_shared/` 找。你打开了 `01_display.ino`，但那个文件夹里没有 `pinmap.h`。

**怎么验证**
1. 打开「文件 → 首选项 → 显示详细输出」，看不到也行；
2. 去资源管理器看 `firmware\01_display\` 里有没有 `pinmap.h` —— 十有八九没有。

**怎么修**（二选一）
- **推荐**：在项目根目录跑一次同步脚本，它会复制到每个 sketch 文件夹：
  ```
  powershell -ExecutionPolicy Bypass -File tools\sync_pinmap.ps1
  ```
  看到 `synced -> firmware\01_display\pinmap.h` 之类就成功了，然后回 IDE **重新编译**。
- 手动：把 `firmware\_shared\pinmap.h` 复制到当前 `.ino` 的同一个文件夹。

> ⚠️ 别把 `pinmap.h` 复制到 Arduino 的 libraries 目录——以后改引脚会改到"不知道哪一份"，本项目的设计是"跟着 sketch 走"。

### A2. 编译报错：`ledcAttach` 或 `ledcSetup` not declared

**现象 A（新代码 + 老核心）**
```
error: 'ledcAttach' was not declared in this scope
```
**现象 B（老代码 + 新核心）**
```
error: 'ledcSetup' was not declared in this scope
error: 'ledcAttachPin' was not declared in this scope
```

**最可能原因**：Arduino-ESP32 核心版本不对。官方 [2.x→3.0 迁移指南](https://docs.espressif.com/projects/arduino-esp32/en/latest/migration_guides/2.x_to_3.0.html) 明确：**core 3.0 删除了 `ledcSetup` 和 `ledcAttachPin`**，改为 `ledcAttach(pin, freq, resolution)` + `ledcWrite(pin, duty)`（参数从"通道"改成"引脚"）。本项目全部按 3.x 写。

**怎么验证**
- IDE 菜单：**工具 → 开发板 → 开发板管理器** → 搜 `esp32` → 看已安装版本号。
- 是 `2.x.x` → 现象 A；是 `3.x.x` 还报 → 你装了两个核心/选了别的板包（见 A4）。

**怎么修**
1. 开发板管理器里把 **esp32 by Espressif Systems 升级到 3.x 最新**（本项目最低 3.0.4，建议直接最新 3.x）；
2. 关掉 IDE 再开（库索引偶尔要重启才生效）；
3. **重新选一次开发板**：`ESP32S3 Dev Module`；
4. 重新编译。

### A3. 编译报错：`i2s_std.h: No such file`

**现象**
```
fatal error: driver/i2s_std.h: No such file or directory
```

**最可能原因**：核心是 **2.x**（底层 ESP-IDF 4.4），那个版本还没有"新 I2S 驱动"，只有老的 `driver/i2s.h`。`i2s_std.h` 是 IDF 5.x（= Arduino core 3.x）才有的。

**怎么验证**：同上，开发板管理器看版本号是不是 2.x。

**怎么修**：升级核心到 3.x（同 A2）。**不要**去网上找 `i2s_std.h` 塞进 libraries——塞进去也编不过，因为底层函数不存在。

---

### A4. 编译报错：`esp_camera.h: No such file`

**现象**
```
fatal error: esp_camera.h: No such file or directory
```

**最可能原因**（按概率）：
1. **开发板选错了**：选成了 `ESP32 Dev Module` / `ESP32-C3` 之类的非 S3 型号；
2. esp32 核心根本没装好（只装了其它厂商的板包）；
3. 你把 `#include "esp_camera.h"` 写进了不带摄像头的工程（比如 `02_motor.ino`）。
4. 极少数情况：核心版本太老（2020 年前的包）。

> 官方说明：[esp32-camera 项目](https://github.com/espressif/esp32-camera) 里写得很清楚——*"If you are using the arduino-esp32 core in Arduino IDE, **no installation is needed**"*。摄像头库是 **核心自带**的，**不需要**在库管理器里另外装。

**怎么验证**
1. 工具 → 开发板：必须显示 `ESP32S3 Dev Module`；
2. 工具 → 开发板管理器：`esp32 by Espressif Systems` 已安装且是 3.x；
3. 看当前打开的 sketch 名字：是不是 `04_camera.ino` / `07_main`。

**怎么修**：把开发板改成 `ESP32S3 Dev Module`，确认核心 3.x，重新编译。**不要在库管理器里装一个叫 "esp32-camera" 的第三方库来"修复"**，版本冲突反而更麻烦（见 A5）。

---

### A5. 编译报错：`camera_config_t` 没有 `pin_sccb_sda`

**现象**（两种都可能出现，说明库版本不同）
```
error: 'camera_config_t' has no member named 'pin_sccb_sda'
```
或
```
error: 'camera_config_t' has no member named 'pin_sscb_sda'
```

**最可能原因**：esp32-camera 把字段名从 `pin_sscb_sda/pin_sscb_scl`（旧拼写）改成了 `pin_sccb_sda/pin_sccb_scl`（新拼写）。核心 3.x 自带的版本用的是**新拼写**；如果你在库管理器里手动装过一个旧版 esp32-camera，Arduino 会优先用那一个 → 报"没有新字段"。

**怎么验证**
- 看报错是哪一个字段名不认；
- 库管理器搜 `esp32-camera`：如果显示"已安装"，说明你手动装过（该删）。

**怎么修**（按顺序）
1. 库管理器里**卸载**手动安装的 `esp32-camera`；
2. 用核心 3.x 自带的版本；
3. 如果卸载后反而报 `pin_sscb_sda` 不存在（说明你的核心自带版本比较老），把 `04_camera.ino` / `07_main` 里那两行改成旧拼写即可：
   ```cpp
   config.pin_sscb_sda = PIN_CAM_SIOD;
   config.pin_sscb_scl = PIN_CAM_SIOC;
   ```
   （只改字段名，引脚宏不要动。）

### A6. 编译报错：`secrets.h: No such file`

**现象**：只在烧 `07_main` 时出现。

**最可能原因**：`secrets.h` 里放 API Key，**故意不提交到仓库**（防止你把自己的 Key 发到网上）。仓库里只有 `secrets.example.h` 模板。

**怎么修**
1. 进入 `firmware\07_main\`；
2. 把 `secrets.example.h` **复制一份**，改名为 `secrets.h`；
3. 用记事本/IDE 打开 `secrets.h`，把里面的 `YOUR_...` 换成你自己的 Key（没有 Key 也能先烧，只是语音功能不能用；第 8 步之前不用管）。

### A7. 编译报错：`TFT_eSPI.h` 或 `Audio.h` 或 `ArduinoJson.h` 找不到

**现象**
```
fatal error: TFT_eSPI.h: No such file or directory
fatal error: Audio.h: No such file or directory
fatal error: ArduinoJson.h: No such file or directory
```

**最可能原因**：这三个都是**库里**的头文件（不是核心自带），库管理器里没装。

| 头文件 | 依赖的库 | 库管理器里搜什么 | 用在哪一步 |
|---|---|---|---|
| `TFT_eSPI.h` | TFT_eSPI（Bodmer） | `TFT_eSPI` | 第 2 步（屏幕）、第 8 步 |
| `Audio.h` | ESP32-audioI2S | `ESP32-audioI2S`（或 `ESP32-audioI2S-master`） | **只有第 8 步**（播 TTS） |
| `ArduinoJson.h` | ArduinoJson（Benoit Blanchon） | `ArduinoJson` | **只有第 8 步**（解析云端 JSON） |

**怎么修**
1. IDE 左侧「库管理器」→ 搜上表名字 → 安装（TFT_eSPI 别忘按 [B2](#b2-屏幕白屏--花屏背光亮但没图像) 覆盖 `User_Setup.h`）；
2. 关掉 IDE 重开；
3. 重新编译。

**怎么验证装没装**：`C:\Users\<你>\Documents\Arduino\libraries\` 里能看到 `TFT_eSPI`、`ESP32-audioI2S`、`ArduinoJson` 三个文件夹。

> 注意：`ESP32-audioI2S` 有好几个同名 fork（作者不同），本项目按 **schreibfaul1/ESP32-audioI2S** 写的，装 4.x 最新版；旧 2.x 在 core 3.x 下大概率编不过。

### A8. 上传时报 `Sketch too big` / `text section exceeds`

**最可能原因**：分区表太小（16MB Flash 却选了默认 `Default 4MB with spiffs`）。

**怎么修**：工具 → Partition Scheme → 选 `16M Flash (3MB APP/9.9MB FATFS)` 或 `Huge APP`；Flash Size 确认 `16MB`。改完重新上传。

### A9. 上传失败：连不上板子

**现象**
```
A fatal error occurred: Could not open COM3 ...
Failed to connect to ESP32-S3: No serial data received.
```

**最可能原因**（按概率）
1. 插的是 **USB 口**（原生 USB），不是 UART 口 → 电脑上根本没有 CP210x 的 COM；
2. 端口选错（选成了别的串口设备）；
3. 板子没进下载模式（少数情况需要手动：**按住 BOOT → 点一下 RST → 松开 BOOT**，再点上传）；
4. 杜邦线/超声波把 GPIO19/20 拉住了（这两个脚被超声波占用，插着 USB 口会互相干扰）；
5. 数据线是"只能充电"的劣质线（没有 D+/D-）。

**怎么验证**
- 设备管理器 → 端口(COM 和 LPT)：插上 UART 口后**应该多出一个 COM**（名字里带 CP210x / USB-SERIAL CH340）。没有 → 换口/换线。
- 把 USB 口那颗线**拔掉**，只用 UART 口再试。

**怎么修**：换到 UART 口 → 选对应 COM → 还不行就 BOOT+RST 手动进下载 → 再不行换根**能传数据**的 USB 线。

### A10. 串口完全没输出

**现象**：上传成功了（IDE 显示 `Writing at 0x... 100%`），但串口监视器一片空白。

**最可能原因**（按概率，这是新手第一大坑）：

| # | 原因 | 怎么验证 | 怎么修 |
|---|---|---|---|
| 1 | **`USB CDC On Boot` 被打开了** | 工具菜单里看这一项 | 改成 **Disabled**，重新编译上传 |
| 2 | **端口选错 / 插错口** | 设备管理器看有没有新 COM | 只插 **UART 口**，选带 COM 的端口 |
| 3 | **波特率不对** | 看 sketch 文件头写的值（本项目基本都是 115200） | 串口监视器右下角改成 **115200** |
| 4 | 程序开头就卡死/重启了 | 按一下 RST，立刻看串口（前 0.5 秒可能出现红字） | 见 [C 反复重启](#c-反复重启专区) |
| 5 | 串口监视器还没打开就先跑了 | 先开串口监视器再按 RST | 打开监视器 → 按板子 RST |
| 6 | 电脑串口被别的软件占用 | 关掉其它 IDE/串口助手 | 只留一个串口工具 |

> 一句话记忆：**"上传成功但没输出" = 99% 是 `USB CDC On Boot` 或端口选错，不是代码问题。**

## B. 屏幕专区

### B1. 屏幕完全不亮（黑屏，背光也没有）

**最可能原因**
1. **BLK/背光脚没接 3V3**（本项目把背光直接接死 3V3，不占 GPIO）；
2. 屏幕 VCC 没接（或接错到 GPIO）；
3. 杜邦线松 / 插到了相邻的空位；
4. 屏幕坏了（个别次品）。

**怎么验证**：断电，用万用表量屏幕 VCC 对 GND 是不是 3.3V；量 BLK 对 GND 是不是 3.3V。

**怎么修**：BLK→3V3、VCC→3V3（不亮再试 5V，见 [B5](#b5-屏幕能亮但完全白屏没有图像)）、GND 共地；重新插紧杜邦线。

### B2. 屏幕白屏 / 花屏（背光亮，但没图像）

**最可能原因**（按概率）
1. **TFT_eSPI 的引脚配置和 pinmap.h 不一致**（最常见）：库里的 `User_Setup.h` 没替换成本项目的 `config/User_Setup.h`；
2. 驱动型号不对（ST7789 被配成了 ILI9341 之类）；
3. RST 没接（本项目 RST 接 3V3，靠上电复位）；
4. 屏幕排线/杜邦线接触不良；
5. DC 和 CS 接反。

**怎么验证**
- 打开 `C:\Users\<你>\Documents\Arduino\libraries\TFT_eSPI\User_Setup.h`，确认这几行和本项目一致：
  ```cpp
  #define ST7789_DRIVER
  #define TFT_MISO -1
  #define TFT_MOSI 47
  #define TFT_SCLK 21
  #define TFT_CS    3
  #define TFT_DC   38
  #define TFT_RST  -1
  #define TFT_BL   -1
  ```
  再确认 `User_Setup_Select.h` 里**只有一行** `#include <User_Setup.h>` 生效（其它 `#include` 都被注释掉）。
- 串口里 `01_display` 会打印它实际用的引脚，和你的接线对一遍。

**怎么修**：用 `config/User_Setup.h` **覆盖**库目录里的 `User_Setup.h`（不是复制到 sketch 文件夹！），然后重新编译。**改完必须重新编译才生效**，光保存没用。

### B3. 屏幕颜色反了（红蓝互换 / 一片偏色）

**最可能原因**：ST7789 面板有 BGR/RGB 两种排列，库的默认值和你的屏不一致。

**怎么修**：在 `01_display`（或 `07_main`）里把初始化后的一句改成反的：
```cpp
tft.invertDisplay(true);    // 颜色整体反相时用
// 或 red/blue 互换时用：
// tft.setRotation(1); 之后加 tft.writecommand(ST7789_MADCTL); tft.writedata(0x08);
```
最简单粗暴的验证：`tft.invertDisplay(true)` / `false` 各试一次，立刻能看出来。

### B4. 画面方向反了 / 要横屏

**怎么修**：改 `tft.setRotation(0~3)` 逐个试（0/2 是竖屏，1/3 是横屏）。本项目默认 **240×320 竖屏**。

### B5. 屏幕能亮但完全白屏、没有图像

**最可能原因**：RST 靠"上电复位"没成功（个别 ST7789 模块的 POR 电路不认）。

**怎么修**（按顺序试）
1. 断电 10 秒再上电，看是否恢复（有的模块要断电才复位）；
2. 把屏幕 **RST 从 3V3 改接到板子的 EN/RST 脚**（按复位键时屏幕一起复位；EN 是高阻输入，这样接是安全的）；
3. 实在不行：把 RST 接到一个能牺牲的 GPIO，并在代码里拉低 100ms 再拉高——但本项目 30 个脚一个不剩，只能临时这样做测试。

### B6. 屏幕花屏（有图但雪花/错位）

**最可能原因**：SPI 线太长/太松；或者 SCLK 太高；或者和其它模块的线绞在一起。

**怎么修**：杜邦线缩短到 10cm 内、SCLK/SDA 不要和电机线并排走；`User_Setup.h` 里把 SPI 频率降到 27MHz（`#define SPI_FREQUENCY 27000000`）再试。

## C. 反复重启专区

**现象**：串口里不断出现这样的块（数字每 3~5 秒刷一次）：
```
rst:0x3 (RTC_SW_SYS_RST),boot:0x8 (SPI_FAST_FLASH_BOOT)
...
Brownout detector was triggered
```
或
```
E (xxx) boot: ...
ets Jul 29 2019 12:21:46
```

**先看 `rst:0x?` 这一行**，它能直接告诉你是哪一类：

| `rst:` 后面的值 / 关键字 | 含义 | 最可能原因 | 去哪一节 |
|---|---|---|---|
| `Brownout detector was triggered` | 电压跌到 3V 以下 | **电源不够**（舵机/电机同时动、电池没电、线太细） | [C1](#c1-重启时串口出现-brownout) |
| `0x3 (RTC_SW_SYS_RST)` | 软件复位，多是看门狗或 panic | 代码卡死/看门狗 | [C2](#c2-重启时串口出现-guru-meditation-或-wdt) |
| `0x8` / `0x9` | 正常上电/复位 | —— | 不用管 |
| `0x7` / `0xc` | 任务看门狗 | 某个循环不让 CPU 喘气 | [C2](#c2-重启时串口出现-guru-meditation-或-wdt) |
| 毫无反应、灯闪一下又灭 | 供电彻底塌了/短路 | 接线短路 | [C1](#c1-重启时串口出现-brownout) |

### C1. 重启时串口出现 Brownout

**最可能原因（按概率）**
1. **5V 电流不够**：舵机和电机同时动，峰值电流把 5V 拉到 3V 以下；
2. **1000µF 电容没接 / 接反 / 虚焊**（本项目用杜邦线，电容脚容易接触不良）；
3. **电池没电**（两节 18650 低于 3.2V/节）；
4. **电池座开关没拨到 HOLD**，或电池方向装反；
5. **杜邦线接触不良**（最阴的一种：动一下就好、不动就重启）。

**怎么验证**
1. 万用表量 5V 母排对 GND：静止时 5.0V 左右；**让轮子转起来的瞬间**看掉到多少（低于 4.3V 就有风险）；
2. 万用表量电池电压：两节都 >3.5V 才算有电；
3. 把车架空（轮子不落地）再跑：如果架空不重启、落地就重启 → 电流问题；
4. 逐个模块断电：只留 ESP32 跑 → 不重启了，说明是某个模块抢电流（通常是舵机或电机）。

**怎么修（按顺序）**
1. **降功率**：`07_main` 里把电机 PWM 上限降到 60~70%，舵机转动时不要同时四轮全速（代码里已有这个约束，别去掉）；
2. **加电容**：1000µF 正极→5V、负极→GND，**正负极别接反**；有第二颗 1000µF 的话再并到舵机供电处；
3. **换供电**：调试阶段直接用 **5V/2A USB 电源**（不用电池），先排除电池问题；
4. **换粗线/短帽**：5V 主供电线用两根杜邦线并联，电机线尽量短；
5. 给电源"软启动"：代码里上电先停 2 秒再动（本项目固件已经是这个策略）。

### C2. 重启时串口出现 Guru Meditation 或 WDT

**现象**
```
Guru Meditation Error: Core 1 panic'ed (LoadProhibited)
Task watchdog got triggered
```

**最可能原因**：某处空指针/数组越界/死循环不让 CPU 让出（多数是改代码改出来的）；或者摄像头/音频初始化失败后没处理。

**怎么验证**
1. 串口里 `Guru Meditation` 后面会跟 `Backtrace: 0x...`，把这段完整复制（不是截图，文本）；
2. 先烧**最简单的 sketch**（`01_display`）看还重不重启：不重启 → 说明是后面的模块程序问题。

**怎么修**
- 不要自己改 `.ino` 里的逻辑（本项目是给零基础用的，改坏了很难查）；
- 把完整报错 + 烧的哪个 sketch + 接了哪些模块发出来（见文末「求助模板」）；
- 临时绕过：先断开摄像头/音频，只跑屏幕，一个个加回来定位。

## D. 摄像头专区

> 摄像头是"杜邦线数量最多"的模块（14 根信号线），**90% 的问题都是线**。查摄像头永远先查线，再怀疑代码。

### D1. 串口报 `0x106` / `0x105` / `0x20001` / `0xFFFFFFFF`（认不到摄像头）

> 不同版本的 esp32-camera 报的码不一样：**最新版认不到摄像头一般是 `0x106`**（ESP_ERR_NOT_SUPPORTED = 探测不到 sensor），驱动内部失败是 `0xFFFFFFFF`（ESP_FAIL）；老版本才用 `0x105` / `0x20001`。**看到哪个都按本节查**。

**含义**：SCCB 总线上**探测不到摄像头**（连"你是谁"都问不到）。

**最可能原因（按顺序查，前三条占 90%）**
1. **D0~D7 有一根没插到底 / 插错位置 / 整排插反**；
2. **RST 没接 3V3**（悬空 → 摄像头一直复位）；
3. **PWDN 没接 GND**（悬空 → 摄像头可能处于掉电状态）；
4. SIOD / SIOC 接反（SDA=SIOD→GPIO16，SCL=SIOC→GPIO17）；
5. 摄像头 3V3 没接，或错接了 5V（接 5V 可能已烧）；
6. 杜邦线太长（>15cm）或接触不良。

**怎么验证**
1. 断电，用万用表通断档，从**摄像头排针**一路量到**ESP32 排针**，一根一根确认（14 根，5 分钟能干完）；
2. 量摄像头 3V3 对 GND 是否 3.3V；
3. 量 RST 对 GND：应该 3.3V；PWDN 对 GND：应该 0V。

**怎么修**：按上面的顺序重插/改正。**不要一上来就怀疑代码**——本项目这套引脚是核对过官方资料的（见 [docs/00_硬件事实核查.md](00_硬件事实核查.md)）。

### D2. 串口报 `0x101`（ESP_ERR_NO_MEM）或一开摄像头就重启

**含义**：申请不到帧缓冲内存。

**最可能原因**：**PSRAM 没开**（N16R8 是 **OPI PSRAM**，不是 QSPI）。

**怎么验证**：串口开头会打印 `[PSRAM] 已就绪：共 xxxx KB` 或 `【严重警告】没有检测到 PSRAM`。

**怎么修**
1. 工具 → **PSRAM → OPI PSRAM**（选 QSPI 会失败）；
2. 工具 → **Flash Size → 16MB**；
3. 工具 → Partition Scheme → `16M Flash (...)` 或 `Huge APP`；
4. **改完必须重新编译上传**（只改选项不重烧没用）。

### D3. 串口报 `0x102`（ESP_ERR_INVALID_ARG）

**含义**：参数不合法，通常是 `pinmap.h` 被改过或复制错。

**怎么修**：跑一次 `powershell -ExecutionPolicy Bypass -File tools\sync_pinmap.ps1`，确认每个 sketch 里的 `pinmap.h` 和 `_shared` 一致，然后重新编译。

### D4. 串口报 `0x20002`

**含义**：帧缓冲申请失败（分辨率太高或 PSRAM 不足）。

**怎么修**：把 `04_camera.ino` 里 `config.frame_size = FRAMESIZE_VGA` 改成 `FRAMESIZE_QVGA` 再试；确认 OPI PSRAM + 16MB Flash。

### D5. 串口刷 `cam_hal: EV-EOF-OVF` / `cam_hal: EV-VSYNC-OVF`

**含义**：摄像头数据流"溢出"——ESP32 没来得及取走数据，或时钟/信号质量差。

**最可能原因（按概率）**
1. **杜邦线太长/太乱**，D0~D7 之间串扰；
2. **XCLK 没接**（GPIO12 必须接，不是可选）；
3. 帧率/分辨率开太高 + WiFi 同时跑；
4. 供电不足（摄像头峰值约 250mA，5V/3V3 被拉低）；
5. 偶发：光照极暗时曝光时间变长也会溢出。

**怎么验证**：先不连 WiFi 只开摄像头看还报不报（改 `04_camera.ino` 临时注释掉连 WiFi——**看不懂就别改，直接跳到修**）。

**怎么修**
1. 把 D0~D7 的线全部换成**最短、最整齐**的那一组，不要绕圈、不要和电机线并排；
2. 确认 XCLK=GPIO12、PCLK=GPIO13、VSYNC=14、HREF=15 一根不差；
3. 摄像头 3V3 单独从 ESP32 的 3V3 取，不要从电池座的 3V3 取；
4. 偶发几条不用管，能出图就是正常。

### D6. 画面黑屏 / 全绿 / 全紫

**最可能原因**：D0~D7 顺序错、PCLK/HREF/VSYNC 接错、摄像头镜头盖没摘（真的，有人忘了）。

**怎么修**：按 docs/01 第 3.1 节逐根对；先撕镜头保护膜。

### D7. 图传卡顿 / 延迟大

**最可能原因**：WiFi 信号弱、同时有多个客户端、分辨率太高。

**怎么修**：手机靠近路由器；**只开一个网页**（MJPEG 流一个连接占满）；`FRAMESIZE_QVGA` 降低分辨率。项目里 `/status` 可以看 fps，正常 VGA 是 10~20 fps。

## E. 音频专区（先功放、后麦克风）

> 顺序很重要：**先跑第 1 级（只放音）听到"嘟"，再去接麦克风**。否则你分不清是功放问题还是麦克风问题。

### E1. 麦克风没数据，或者数值一直很小

**现象**：串口电平表 `RMS` 一直是 0~200，说话也不动。

**最可能原因（按概率）**
1. **INMP441 的 L/R 没接 GND**（悬空/接 3V3 → 数据跑到右声道，代码取左声道 → 永远是静音）；
2. **SD/DOUT 没接 GPIO41**，或接到了别的脚；
3. VDD 接错（必须 3V3，接 5V 会烧）；
4. **BCLK/WS 接反**（BCLK→GPIO39，WS→GPIO40）；
5. 麦克风 GND 没接（少一根 GND）；
6. 第 2 级代码 `TEST_LEVEL` 没改（还在跑第 1 级）。

**怎么验证**
1. 看串口开头：`[OK] I2S RX 已启动：BCLK=GPIO39 WS=GPIO40 SD=GPIO41` —— 和你接的对一遍；
2. 万用表量 INMP441：VDD-GND 3.3V、L/R-GND 0V；
3. 对着麦克风**拍手**：条形图完全不动 = 没数据；动一点点 = 有数据但增益小。

**怎么修**：L/R 接 GND；SD 接 GPIO41；VDD 接 3V3；BCLK/WS 别接反；所有 GND 共地。

> 如果确认接对了还是没数据：这是**项目约定的"分时复用"**在起作用——检查 `05_audio.ino` 里是不是有残留的 TX 没释放（串口会打印 `[WARN] 释放 TX 时有小问题`）。按 RST 重开一次。

### E2. 功放没声，或者只有"咔咔"声

**现象 A：完全没声**（第 1 级就没有"嘟"）

**最可能原因**
1. **SD/SHDN 没接 3V3**（接地或悬空 = 静音/关断）；
2. **VIN 没接 5V**（接 3V3 能响但很小）；
3. 喇叭没插到功放的 PH2.0 座 / 喇叭线断；
4. BCLK/WS/DIN 接错（DIN→GPIO42）；
5. 第 1 级代码没选（`TEST_LEVEL` 不是 1）。

**怎么验证**
- 万用表量：SD 对 GND = 3.3V；VIN 对 GND = 5V；
- 用手指轻碰喇叭纸盆：完全没有"哒"声 → 喇叭/功放可能坏了；上电瞬间有"啪" → 功放是活的，是信号问题。

**怎么修**：SD→3V3、VIN→5V、DIN→GPIO42、喇叭插紧；先只跑第 1 级。

**现象 B：只有"咔咔"声 / 沙沙声**

**最可能原因**
1. **MAX98357A 的 SD 接 3V3 = 常开**，录音（I2S RX）期间它照样收到 BCLK/WS，DIN 上没数据 → 轻微咔咔。**这是正常现象**，不是坏了；
2. 如果"咔咔"很大：5V 电源纹波大（电容没接/电池没电）；
3. 如果是"嗡嗡"：功放输入悬空 + 电源干扰。

**怎么修**：接受轻微咔咔（设计如此，30 个脚没有多余的去控 SD）；如果是刺耳大噪声 → 检查 1000µF 电容、电源。

**现象 C：声音很小**

**怎么修**：GAIN 悬空 = 9dB（默认）；把 GAIN 接 GND = 12dB（注意：GAIN 接 GND 后音量变大但底噪也大）；确认 VIN 是 5V 不是 3.3V；确认 SD 是 3.3V（>1.4V = 左声道满幅）。

### E3. 第 3 级回放时重启

**最可能原因**：播放电流冲击（喇叭 3W 峰值）+ 5V 余量不足。

**怎么修**：**1000µF 必须接**；本项目代码已经把回放幅度限制在 60% 以内，不要自己把 `kMaxPlayAmp` 调大。

## F. 舵机专区

### F1. 舵机抖动 / 一动就重启

**最可能原因（按概率）**
1. **舵机红线接了 3V3**（带不动，必须 5V）；
2. **5V 电流不够**（两颗 SG90 堵转 + 电机启动 → 5V 塌 → 重启，见 [C1](#c1-重启时串口出现-brownout)）；
3. 舵机地线没共地（只有信号线接了，地线没接）；
4. PWM 信号受干扰（信号线和电机线捆在一起）。

**怎么修**：红线→5V；地线单独拉回电池座 GND；1000µF 电容（主母线 + 舵机旁各一颗）；信号线远离电机线。

### F2. 舵机乱转 / 一直往一个方向转到底

**最可能原因**
1. 信号线接错引脚（水平=GPIO18，俯仰=GPIO48）；
2. 舵机型号不是 SG90（有些 360° 连续旋转舵机，收到 PWM 只会一直转）；
3. 供电电压不稳导致控制电路复位。

**怎么修**：确认两根信号线分别接 18/48；确认买的是 **180° 舵机**（不是 360°/连续旋转版）；稳定 5V。

### F3. 舵机不动

**怎么修**：查 5V 红线、GND、信号线；先跑 `03_servo` 单独测试；上电时舵机会先回中位（代码行为），不动说明没收到信号。

> ⚠️ 提醒：**俯仰舵机（GPIO48）会让板载 RGB 灯偶尔闪**——因为 v1.0 板的 RGB LED 就在 GPIO48 上（v1.1 板在 GPIO38 上，对应屏幕 DC）。**这是正常的，不是坏了**，详见 [docs/00](00_硬件事实核查.md) §2.8。

## G. 电机专区

### G1. 电机完全不转

**最可能原因（按概率）**
1. **TB6612 的 STBY 没接 3V3**（没拉高 = 待机，输出全关）；
2. **PWMA/PWMB 没接 3V3**（本项目用方向脚吃 PWM，这两个必须拉满）；
3. VM 没接 5V（接 3V3 电机转不动）；
4. 电机线没接 AOUT/BOUT，或两个电机并联时红黑接反；
5. 上电时电机就是停的（**这是设计**：上电必须停，见 `02_motor.ino`）。

**怎么验证**：万用表量 TB6612：VCC=3.3V、VM=5V、STBY=3.3V、PWMA/PWMB=3.3V；让程序前进时量 AIN1/AIN2 对地电压（应该有变化）。

**怎么修**：STBY→3V3、PWMA/PWMB→3V3、VM→5V、GND 共地。

### G2. 只往一个方向转 / 不能后退

**最可能原因**：一对方向脚里有一根没接好/接错（AIN1/AIN2 或 BIN1/BIN2）。

**怎么修**：按 docs/01 第 3.5 节核对 AIN1=GPIO1、AIN2=GPIO2、BIN1=GPIO45、BIN2=GPIO46。

### G3. 一边快一边慢 / 跑偏

**最可能原因**：两个电机个体差异（TT 电机很常见）；轮子没装紧；地面打滑。

**怎么修**：代码里有 `MOTOR_LEFT_TRIM` / `MOTOR_RIGHT_TRIM`（或类似微调），把慢的一边调高 5%~10%。

### G4. 电机一转，屏幕花 / 板子重启

**最可能原因**：电机干扰 + 电源塌陷（见 [C1](#c1-重启时串口出现-brownout)）。

**怎么修**：电机线远离屏幕 SPI 线；加电容；降低 PWM。

## H. 超声波专区

### H1. 一直显示 0 / 固定值 / 乱跳

**最可能原因**
1. **TRIG/ECHO 接反**（TRIG=GPIO19，ECHO=GPIO20）；
2. **VCC 接了 5V 而 ECHO 直接进 GPIO20**（5V 打进 3.3V 引脚，可能已经击穿）——本项目要求 VCC 必须 3.3V；
3. 探头被遮挡 / 对着吸音材料（地毯、窗帘）；
4. ECHO 线太长、干扰大；
5. 上电第一次读数异常（GPIO19/20 上电有约 60µs 毛刺，正常）——代码已丢弃前 3 次读数。

**怎么验证**：万用表量 VCC 对 GND 是不是 3.3V；量 ECHO 在测距时对 GND 的**最高电压**：≤3.3V 安全，≈5V 必须加分压。

**怎么修**：VCC→3V3；TRIG→19、ECHO→20；ECHO 若是 5V 版，加 1k+2k 分压再进 GPIO20；探头前方 30cm 内别有软东西。

### H2. 避障不灵敏/撞上去才停

**怎么修**：这是软件阈值（`07_main` 里 `<15cm 停`），先确认超声波单测准确（第 5 步能过），再看代码阈值；电池电压低也会影响测距距离。

## I. WiFi 专区

### I1. 连不上 WiFi（串口一直打印 `.....` 和中文提示）

**最可能原因（按概率）**
1. **用了 5GHz 热点**（ESP32-S3 只支持 **2.4GHz**）——路由器/手机热点通常有 `xxx` 和 `xxx_5G` 两组；
2. SSID/密码写错（多了空格、大小写、中文 SSID）；
3. 热点名称带**中文**（很多设备握手失败）；
4. 手机热点没开"最大兼容性/2.4GHz"；
5. 信号太弱（板子离路由器远，或天线被电机/电池挡住）；
6. 路由器开了 MAC 白名单/企业认证（WPA2-Enterprise 不支持）。

**怎么验证**
- 串口开机时会**扫描附近热点**并打印列表（`04_camera.ino` 的 `WIFI_SCAN_AT_BOOT`），看列表里有没有你家 WiFi：**没有 = 它是 5GHz 或太远**；
- 用手机开热点、名字改成纯英文（如 `robot123`）再试，能连上说明是路由器/SSID 问题。

**怎么修**：改 `04_camera.ino` / `07_main` 顶部的 `WIFI_SSID` / `WIFI_PASS` → 换成 **2.4G 那一组**的纯英文名字 → 重新编译上传（改完必须重烧，不是按 Ctrl+U）。

### I2. 连上了但很快掉线

**怎么修**：确认 `WiFi.setSleep(false)` 在（本项目代码已加）；离路由器近一点；USB 供电电流足。

## J. HTTP 图传专区

### J1. 浏览器打不开 `http://<IP>/`

**最可能原因（按概率）**
1. **手机和机器人不在同一个 WiFi**（手机连了 5G/流量）；
2. 手机开着"移动数据"，浏览器走了蜂窝网络：**先关掉 4G/5G**；
3. **IP 变了**：重新上电后路由器分配了新 IP，看串口打印的新 IP；
4. 防火墙/路由器 AP 隔离（"访客网络"通常禁止设备互访）；
5. 电脑用了代理/VPN；
6. IP 输错（漏了 `http://` 或多了空格）。

**怎么验证**：在电脑 `cmd` 里 `ping <IP>`（电脑也要连同一个 WiFi）。ping 不通 → 网络层问题；ping 通但网页打不开 → 端口/浏览器问题。

**怎么修**：同一 WiFi + 关移动数据 + 用串口打印的最新 IP + 关代理 + 关"访客网络"。手机浏览器如果缓存了旧页面，换个浏览器或隐身模式。

### J2. 网页打得开，但画面一直转圈/黑屏

**最可能原因**
1. **摄像头没出图**（先看串口有没有 `[摄像头] 初始化成功`）；
2. **同时有多个页面在看**（MJPEG 流一个连接占满，第二个连接会等）；
3. WiFi 带宽不够（离得远）；
4. 浏览器不支持 MJPEG（Safari 对 multipart 支持一般，建议 Chrome/Edge/安卓浏览器）。

**怎么修**：关掉其它页面/标签；先打开 `http://<IP>/capture` 看单张能不能出（能出 = 摄像头没问题，是流的问题）；换浏览器。

### J3. 图传正常，但一开就卡住/断

**怎么修**：降低分辨率（`FRAMESIZE_QVGA`）；确认 5V/2A 供电；手机离近点。看 `/status` 的 fps 和 RSSI。

## K. 云端语音专区

> 只有做到第 8 步才需要看这节；前面 7 步跟云端无关。

| 现象 | 最可能原因 | 怎么验证 | 怎么修 |
|---|---|---|---|
| 按住 BOOT 说话没反应 | 没进第 8 步程序 / `secrets.h` 没建 / Key 空 | 串口看有没有 `[语音]` 开头的日志 | 按 [A6](#a6-编译报错secretsh-no-such-file) 建 `secrets.h` |
| 串口报 `401` / `403` | API Key 错、没开通服务、余额不足 | 去云控制台看 Key 和开通状态 | 改 `secrets.h` 里的 Key；确认开通了 ASR/TTS |
| 串口报超时 / `-1` | WiFi 信号差 / 云端地址写错 | `ping` 云服务域名；看串口 RSSI | 靠近路由器；核对 docs/05 里的地址 |
| 能听到 TTS 但没动作 | 大模型没按格式返回动作指令 | 串口会打印模型原始回复 | 换模型/换提示词（见 docs/05） |
| 录音上传后识别为空 | 麦克风没数据（先过第 7 步） | 回到 [E1](#e1-麦克风没数据或者数值一直很小) | 先修麦克风 |

## L. 5 分钟急救卡（不知道怎么查时按这个顺序）

1. **看串口**：有没有输出？没有 → [A10](#a10-串口完全没输出)；有乱码 → 波特率/插错口。
2. **看 `rst:` 开头**：Brownout → 电源（[C1](#c1-重启时串口出现-brownout)）；Guru → 代码（[C2](#c2-重启时串口出现-guru-meditation-或-wdt)）。
3. **断电重新插一遍所有杜邦线**（尤其是 GND），再上电。**接触不良能伪装成任何 bug。**
4. **只留一个模块**：拔掉其他模块，只跑最小 sketch，再一个个加回来。
5. **量三个电压**：电池 ≥7.0V、5V 母排 ≥4.8V、3V3 ≥3.2V。
6. **换 USB 供电**：不接电池，用 5V/2A 电源，排除电池问题。
7. 都不行 → 用下面的模板求助。
