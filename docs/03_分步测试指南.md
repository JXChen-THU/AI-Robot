# 03 · 分步测试指南（8 关，一关一关过）

> **铁律：前一关不通过，绝对不要接下一个模块。**
> 这个项目的引脚一个不剩、7 个模块挤在一块板子上，一次全接上再排查，会把你逼疯。
> 8 关的顺序是刻意排的：**先证明板子活着 → 再逐个证明"每根线"活着 → 最后才让它们一起动**。
>
> 每一关都按同一个格式写：**上电前检查 → 接什么线 → 烧哪个程序 → 预期串口输出 → 预期现象 → 通过标准 → 不通过怎么办**。
> 看不懂的报错，直接去 [docs/04_排错手册.md](04_排错手册.md) 搜原文。

## 0. 通用准备（每一关都适用）

### 0.1 烧录设置（Arduino IDE 2.x → 工具菜单）

| 菜单项 | 必须选 | 选错的后果 |
|---|---|---|
| 开发板 | **ESP32S3 Dev Module** | 选成 ESP32 Dev Module → 摄像头/PSRAM 全废 |
| Flash Size | **16MB** | 选 4MB → 上传报 `Sketch too big` |
| PSRAM | **OPI PSRAM** | 选 QSPI/Disabled → 摄像头初始化失败、音频缓冲申请失败 |
| Partition Scheme | `16M Flash (3MB APP/9.9MB FATFS)`，没有就 `Huge APP` | 默认 4MB → 装不下 |
| USB CDC On Boot | **Disabled** | 打开 → 串口监视器一个字都没有 |
| CPU Frequency | 240MHz（默认） | 降频 → 摄像头/音频卡 |
| 端口 | 选**带 COM** 的那个（UART 口 = CP210x） | 选错 → 上传失败 |
| 上传速度 | 921600 或 460800（连不上就降到 115200） | 太高 → `Failed to connect` |

**烧录线必须插 `UART` 口那颗 Type-C。`USB` 口平时不要插**（GPIO19/20 被超声波用了，见 [docs/01](01_接线总表.md) 第 5 节）。

### 0.2 每一关开始前的固定 3 个动作

```
① 跑一次引脚同步：  在项目根目录执行   powershell -ExecutionPolicy Bypass -File tools\sync_pinmap.ps1
   （它会把 firmware\_shared\pinmap.h 复制进每个 sketch 文件夹，不跑会报 pinmap.h: No such file）
② 打开正确的 .ino： 文件路径见每一关的"烧哪个程序"
③ 点"上传"，看到 100% 后，再点串口监视器（115200）
```

> **不要**把 `firmware` 整个文件夹当项目打开。Arduino 要求"一个文件夹里只能有一个 `.ino`"，本项目每个模块是一个独立小工程，**单独打开各自的 `.ino`**。

### 0.3 三种供电方式（不同关卡用不同供电）

| 供电方式 | 怎么接 | 什么时候用 | 注意 |
|---|---|---|---|
| **A. 只插 UART USB** | 电脑 → UART 口 | 第 1、2 关（空板/屏幕） | 板子 5V/3V3 都从 USB 来，屏幕、超声波够用 |
| **B. 电池（HOLD 常开）** | 电池座 → ESP32 5V、TB6612 VM、舵机 5V… | 第 3 关以后（电机/舵机/功放） | 峰值电流大，USB 口带不动；**车要架空** |
| **C. 5V/2A USB 电源直供** | 5V 电源 → ESP32 的 `5V` 脚（不是插口） | 没有电池时的替代方案 | 5V 只能进 `5V` 脚，**绝不能进 3V3 脚** |

> ⚠️ **电池和 UART USB 同时接**：为了在电池供电时还能看串口，很多教程会让你两个都插。本项目**不推荐长期这样**（等于两个 5V 电源并联，官方原理图的防倒灌电路我没有逐页核实）。**做法**：需要看串口时短暂插上 UART，看完拔掉；如果发现 5V 母排电压 >5.5V 或板子发烫，立刻拔掉。
> 最稳的办法：**先用 USB 供电把代码烧进去并确认串口正常，再切电池看动作**。

### 0.4 一根线的安全习惯

- 每次插拔前**先断电**（拨电池座开关到 OFF，或拔 USB）。
- 所有模块 **GND 必须接到同一个电网**，少一根 GND 会表现为"代码有 bug"。
- 杜邦线插好后**轻轻拉一下**，能拉动就是没插好。

## 第 1 关：空板点灯（不接任何模块）

> **上电前检查**：桌上只放开发板 + 一根 UART 数据线，**屏幕上没有任何模块**；确认是 `UART` 口不是 `USB` 口。

### 接什么线
**什么都不接。** 这一关只验证：电脑能不能烧程序、串口能不能说话、板载 RGB 灯亮不亮。

### 烧哪个程序
新建一个空 sketch（文件 → 新建），把下面这段**整段复制粘贴**进去，覆盖原来的内容：

```cpp
/* 第 1 关：空板自检。不接任何模块，只验证串口 + 板载 RGB 灯。
 * 板载 RGB 灯：v1.0 初版在 GPIO48，v1.1 在 GPIO38（见 docs/00 §2.8）。
 * 先试 48，灯不亮就把 48 改成 38 再烧一次 —— 哪个亮用哪个。 */
#define MY_RGB_PIN 48

void setup() {
  Serial.begin(115200);
  delay(500);
  Serial.println();
  Serial.println("======================================");
  Serial.println(" AI-Robot 第 1 关：串口正常！");
  Serial.println("======================================");
  Serial.printf("芯片型号 : %s\n", ESP.getChipModel());
  Serial.printf("Flash    : %u MB\n", (unsigned)(ESP.getFlashChipSize() / (1024UL * 1024UL)));
  Serial.printf("PSRAM    : %u KB\n", (unsigned)(ESP.getPsramSize() / 1024UL));
  Serial.println("板载 RGB 灯会红/绿/蓝各闪一下...");
}

void loop() {
  neopixelWrite(MY_RGB_PIN, 32, 0, 0); delay(400);   // 红
  neopixelWrite(MY_RGB_PIN, 0, 32, 0); delay(400);   // 绿
  neopixelWrite(MY_RGB_PIN, 0, 0, 32); delay(400);   // 蓝
  neopixelWrite(MY_RGB_PIN, 0, 0, 0);  delay(1200);  // 灭
}
```

### 预期串口输出（115200）
```
======================================
 AI-Robot 第 1 关：串口正常！
======================================
芯片型号 : ESP32-S3
Flash    : 16 MB
PSRAM    : 8192 KB
板载 RGB 灯会红/绿/蓝各闪一下...
```

### 预期现象
- 串口监视器每 2.4 秒重复一次上面内容（不会重复打印 __setup__ 那几行，但 RGB 会一直循环闪）；
- 板载那颗小 RGB 灯**红 → 绿 → 蓝 → 灭**循环。

### 通过标准（全中才算过）
- [ ] 串口能打印出 "AI-Robot 第 1 关：串口正常！"
- [ ] Flash 显示 **16 MB**
- [ ] PSRAM 显示 **8192 KB**（不是 0）
- [ ] 板载 RGB 灯能红/绿/蓝闪

> 如果 PSRAM 是 0：工具 → PSRAM → 选 **OPI PSRAM**，重新上传（只改选项不重烧没用）。
> 如果 RGB 不亮：把 `#define MY_RGB_PIN 48` 改成 `38` 再烧（板子版本差异）。
> 如果编译报 `neopixelWrite was not declared`：核心太老，升级到 Arduino-ESP32 **3.x**。

### 不通过怎么办

| 现象 | 最可能原因 | 去哪看 |
|---|---|---|
| 串口一个字都没有 | 插了 USB 口 / USB CDC 被打开 / 波特率不对 | [docs/04 A10](04_排错手册.md#a10-串口完全没输出) |
| 上传报 `Failed to connect` | 端口选错 / 需要 BOOT+RST / 劣质数据线 | [docs/04 A9](04_排错手册.md#a9-上传失败连不上板子) |
| 反复重启 | 板上没有该有的模块却短路了 | [docs/04 C](04_排错手册.md#c-反复重启专区) |
| RGB 怎么改都不亮 | 板子版本不同/灯坏；**不影响后续进度** | 跳过，继续第 2 关 |

## 第 2 关：屏幕 ST7789（2.4 寸 240×320）

> **上电前检查**：断电状态下确认屏幕 **VCC→3V3（不是 5V）**、**GND 共地**、**RST 和 BLK 都接 3V3**；屏幕排针没有插反。

### 接什么线（7 根）

| 屏幕丝印 | 接到 | 备注 |
|---|---|---|
| VCC | 3V3 | 绝对不要 5V |
| GND | GND | |
| SCL / SCK / CLK | **GPIO21** | |
| SDA / MOSI / DIN | **GPIO47** | |
| CS | **GPIO3** | 就是启动脚 3，别怀疑 |
| DC / RS | **GPIO38** | |
| RES / RST | **3V3** | 不占 GPIO |
| BLK / LED | **3V3** | 不占 GPIO，屏幕常亮 |

### 烧哪个程序
`firmware/01_display/01_display.ino`

**烧之前必须先做（只做一次）**：
1. 库管理器装 **TFT_eSPI**（作者 Bodmer，2.5.x）；
2. 把项目里的 `config/User_Setup.h` **复制覆盖**到
   `C:\Users\<你>\Documents\Arduino\libraries\TFT_eSPI\User_Setup.h`；
3. **关掉 IDE 再打开**（TFT_eSPI 只在启动时读配置）。

> 忘了第 2 步会怎样？编译会直接报 `[TFT_eSPI not configured] ...`（代码里有编译期检查，不会让你白屏烧进去）。

### 预期串口输出
```
==================================================

==================================================
[OK] 串口正常 (115200)
[OK] 屏幕引脚: SCLK=GPIO21  MOSI=GPIO47  CS=GPIO3  DC=GPIO38
[OK] RST->3V3  BLK->3V3  VCC->3V3 (这 3 根不占 GPIO)
[OK] 屏幕规格: 240 x 320, SPI 40000000 Hz
[OK] TFT_eSPI 初始化完成（白屏请查 User_Setup.h / RST / BLK）
[OK] 显示引脚表
[OK] 开始色块测试
[OK] 色块 RED
[OK] 色块 GREEN
[OK] 色块 BLUE
[OK] 显示标题
[OK] 进入表情循环（目标 20fps），底部显示运行时间
```

### 预期现象（按顺序）
1. 屏幕刷出 **引脚表**（SCLK/MOSI/CS/DC 的 GPIO 号）；
2. 全屏 **红 → 绿 → 蓝** 各 0.6 秒；
3. 出现 **"AI-Robot v1.0" + 中文"桌面机器人" + "Desktop Robot"**；
4. 进入表情循环：深蓝色"脸"，两只青绿色眼睛左右看、每 3.2 秒眨一次眼；
5. 底部左边 `T+12.3s` 在走字，右边 `FPS 19` / `FPS 20`。

### 通过标准
- [ ] 串口出现 `[OK] TFT_eSPI 初始化完成`
- [ ] 红/绿/蓝三个色块颜色**正确**（红就是红，不是蓝）
- [ ] 能看到中文"桌面机器人"（5 个 24×24 点阵字）

- [ ] 底部 FPS ≥ 18

### 不通过怎么办

| 现象 | 最可能原因 | 去哪看 |
|---|---|---|
| 屏幕不亮（背光也没有） | BLK/VCC 没接 3V3 | [docs/04 B1](04_排错手册.md#b1-屏幕完全不亮黑屏背光也没有) |
| 白屏/花屏（背光亮） | `User_Setup.h` 没覆盖 / 引脚不对 / SPI 太快 | [docs/04 B2](04_排错手册.md#b2-屏幕白屏--花屏背光亮但没图像) |

## 第 3 关：电机 TB6612（★ 车必须架空）

> **上电前检查**：断电，**把车架在四个垫块上让四个轮子悬空**；确认 **TB6612 的 VM=5V（不是 7.4V 电池原压）**、**VCC=3V3**、**STBY=3V3**、**PWMA/PWMB 都接 3V3**、所有 GND 共地、5V 上并了 1000µF 电容（正负极别接反）。

### 接什么线（信号 4 根 + 电源/使能）

| TB6612 丝印 | 接到 | 备注 |
|---|---|---|
| VM | **5V** | 电机额定 3–6V，别接电池 7.4V |
| VCC | **3V3** | 逻辑电源 |
| GND | GND | 必须共地 |
| STBY | **3V3** | 拉高才工作，**最常见的不转原因** |
| PWMA / PWMB | **3V3** | 本项目方向脚吃 PWM，这两个拉满 |
| AIN1 / AIN2 | **GPIO1 / GPIO2** | 左轮 |
| BIN1 / BIN2 | **GPIO45 / GPIO46** | 右轮 |
| AOUT1/AOUT2 | 左边两个电机（红接红、黑接黑，并联） | |
| BOUT1/BOUT2 | 右边两个电机（同上） | |

### 烧哪个程序
`firmware/02_motor/02_motor.ino`

### 预期串口输出
```
==================================================
 AI-Robot v1.0 | 02_motor | TB6612 x4 TT motor
==================================================
[OK] 串口正常 (115200)
[OK] 电机方向脚: AIN1=GPIO1  AIN2=GPIO2  BIN1=GPIO45  BIN2=GPIO46
[OK] PWMA=3V3  PWMB=3V3  STBY=3V3  （方向脚直接输出 PWM）
...
[OK] 4 路 PWM 初始化完成
[OK] 电机已置为静止状态
[OK] 1.5 秒后开始自动测试序列（请确认车已架空）

---- 自动测试开始 ----
[OK] 1/6 前进 2 秒（左 +600‰ / 右 +600‰）
[OK] 2/6 滑行停止（软减速 0.7 秒）
[OK] 3/6 后退 2 秒（左 -600‰ / 右 -600‰）
[OK] 4/6 原地左转（左轮后退 / 右轮前进）
[OK] 5/6 原地右转（左轮前进 / 右轮后退）
[OK] 6/6 刹车演示（两脚同时拉高 = 电机绕组短接）
[OK] 一轮测试结束，3 秒后自动重复
```

### 预期现象
- 上电后先停 1.5 秒（这是安全设计），然后按顺序动：**前进 2s → 停 → 后退 2s → 停 → 原地左转 → 停 → 原地右转 → 停**，3 秒后循环；
- 每次启动/换向都是**慢慢加速**（约 0.15 秒到 60%），没有"咔"的猛冲；
- 四个轮子**方向一致**：前进时四个轮子都往车头方向转。

### 通过标准
- [ ] 串口出现 `[OK] 4 路 PWM 初始化完成`
- [ ] 前进/后退都动，方向正确
- [ ] 原地左转时左轮反转、右轮正转（俯视逆时针）
- [ ] 启动/换向是"缓加速"，没有猛冲
- [ ] **全程没有重启**（串口没有 `rst:0x...` / `Brownout`）
- [ ] 停车时车轮自由滚动（滑行，不是抱住）

### 不通过怎么办

| 现象 | 最可能原因 | 去哪看 |
|---|---|---|
| 完全不转 | STBY/PWMA/PWMB 没接 3V3 | [docs/04 G1](04_排错手册.md#g1-电机完全不转) |
| 只一个方向转 | 一对方向脚里有一根没接好 | [docs/04 G2](04_排错手册.md#g2-只往一个方向转--不能后退) |
| 轮子转向反了 | 线接反/电机装反 | 改 `MOTOR_LEFT_INVERT`/`MOTOR_RIGHT_INVERT` 为 1，不用拆线 |
| 一动就重启（`Brownout`） | 5V 电流不够/电容没接/电池没电 | [docs/04 C1](04_排错手册.md#c1-重启时串口出现-brownout) |
| 一边快一边慢 | TT 电机个体差异 | [docs/04 G3](04_排错手册.md#g3-一边快一边慢--跑偏) |
| 只有嗡嗡声不转 | BIN1/BIN2 接错到别的脚 / 电池电压低 | 检查 45/46 两根线与电池电压 |
| 上电瞬间轮子抽一下 | GPIO45/46 是启动脚，TB6612 下拉保护；**属正常** | 不用管 |

## 第 4 关：云台 SG90 ×2

> **上电前检查**：断电，确认两个舵机 **红线→5V（不是 3V3）**、**棕/黑→GND**、信号线 **水平=GPIO18、俯仰=GPIO48**；舵机云台**可以自由转动、没有被雪弗板卡住**。

### 接什么线（每个舵机 3 根）

| 舵机线色 | 接到 | 备注 |
|---|---|---|
| 棕 / 黑（-） | GND | 单独拉线回电池座 GND 更好 |
| 红（+） | **5V** | 接 3V3 带不动会抖 |
| 橙 / 黄（S） | 水平=**GPIO18**，俯仰=**GPIO48** | |

### 烧哪个程序
`firmware/03_servo/03_servo.ino`

### 预期串口输出
```
==================================================
 AI-Robot v1.0 | 03_servo | SG90 x2 pan/tilt
==================================================
[OK] 串口正常 (115200)
[OK] 水平舵机 PAN  信号 = GPIO18
[OK] 俯仰舵机 TILT 信号 = GPIO48
[OK] 两个舵机红线接 5V、棕/黑线接 GND（千万别接 3V3）
[OK] 舵机参数: 50Hz, 脉宽 500~2500 us (= 0~180 度)
[OK] 扫动范围: 水平 30~150 度, 俯仰 45~135 度
[OK] 两个舵机已绑定
[OK] 已发送中位 90°/90°，等待舵机到位...
[OK] 开始平滑扫动（每 20ms 走 1 度）
[OK] -> 左上角: 水平 30 度 / 俯仰 45 度
...
```

### 预期现象
1. 上电瞬间两个舵机**快速"甩"到中位**（90°/90°）——SG90 没有掉电记忆，这一下是正常的；
2. 然后按 **左上 → 左下 → 右下 → 右上 → 回中** 的顺序平稳转一圈，每段约 2 秒；
3. 全程没有猛甩、没有"咔咔"打齿声；
4. 串口每切换一个角打印一行 `[OK] -> ...`。

### 通过标准
- [ ] 两个舵机都能动（不是在原地嗡嗡抖）
- [ ] 上电先回中位
- [ ] 扫动是平滑的一格一格走，不是猛甩

```
→ 7 先"嘟"后"听" → 8 全网一起动
```

**任何一关不过，退回上一关重测，不要把问题带进下一关。**

## 附录 B：每一步"为什么"（一句话）

| 关 | 为什么排这个顺序 |
|---|---|
| 1 | 先证明"电脑—线—板子"这条链路是通的，排除一切软件环境问题 |
| 2 | 屏幕是**唯一能给你"完整反馈"**的模块，后面所有调试都靠它显示状态 |
| 3 | 电机最容易把电源拉塌，**架空测试**把"电流问题"和"机械问题"分开 |
| 4 | 舵机和电机共用 5V，第 3 关电源过了再上舵机，才知道重启是谁的锅 |
| 5 | 超声波只有 4 根线，最容易验证；它是第 8 关避障的数据来源 |
| 6 | 摄像头线最多、最容易失败，放在电源和基础模块都稳定之后 |
| 7 | 音频分三级，**先用纯正弦波证明功放**，再接麦克风，避免"两个都怀疑" |
| 8 | 前 7 关都过，第 8 关才只需要调软件，不用再动硬件 |
