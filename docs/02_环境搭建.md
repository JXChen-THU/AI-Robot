# 02 · 环境搭建（跟着做 15 分钟，一次配好不用再碰）

> 目标：把电脑配成"点一下就能烧代码"的状态。
> 你现在**还没有收到硬件也没关系**，这一章完全可以先做完。

---

## 1. 装 Arduino IDE 2.x

1. 打开 <https://www.arduino.cc/en/software> → 下载 **Arduino IDE 2.x**（Windows 版，选 "Windows Win 10 and newer, 64 bits"）
2. 一路下一步安装。安装时**勾选** "Install USB driver"（如果它问）。
3. 打开 IDE，界面是英文的，先不用管——我们的代码注释全是中文。

> 为什么不推荐 PlatformIO？对你来说 Arduino IDE 的报错和上传按钮更直观。等你想升级再换。

---

## 2. 让 IDE 认识 ESP32-S3（关键一步）

### 2.1 添加开发板地址
`File` → `Preferences`（快捷键 `Ctrl + ,`）

在 **Additional boards manager URLs** 里粘贴这一行（如果框里已有内容，用逗号隔开追加）：

```
https://espressif.github.io/arduino-esp32/package_esp32_index.json
```

点 `OK`。

### 2.2 安装 ESP32 开发板包
左侧栏点**开发板图标**（或 `Tools` → `Board` → `Boards Manager`），搜索 `esp32`：

- 找到 **esp32** by **Espressif Systems**
- 安装版本 **选 3.x**（3.0.7 或更新的 3.x 都行；**不要装 2.x**，我们的代码是按 3.x 写的）

> ⚠️ 这一步会下载 ~1GB，网络慢的话去泡杯茶。安装失败就再点一次，它会续传。

### 2.3 装 CP2102 驱动（如果 IDE 找不到端口）
你的板子用 CP2102 芯片做串口。Windows 10/11 一般自带驱动，插上就能看到 `COMx`。
看不到端口的话，去 <https://www.silabs.com/developer-tools/usb-to-uart-bridge-vcp-drivers> 下载 CP210x 驱动装上，重插。

---

## 3. 装 4 个库（第 5 个 esp32-camera 先别装）

左侧栏点**库图标**（或 `Tools` → `Manage Libraries`），逐个搜索安装：

| 库名（搜索框里输入） | 作者 | 版本要求 | 用途 |
|---|---|---|---|
| `TFT_eSPI` | Bodmer | **2.5.43 或更新** | 屏幕 |
| `ESP32Servo` | Kevin Harrington / madhephaestus | **3.x**（1.x 在 core 3.x 编不过） | 舵机 |
| `ESP32-audioI2S` | schreibfaul1 | **4.x 最新版**（3.x 也行；**2.x 不行**） | 播放云端 TTS 的 mp3 |
| `ArduinoJson` | Benoit Blanchon | **7.x** | 解析云端返回的 JSON |
| `esp32-camera` | Espressif | **先别装** ⚠️ | 摄像头 |

> ⚠️ **`esp32-camera` 先不要装**：Arduino-ESP32 核心通常自带驱动。如果你在库管理器里装了一个旧版，它会覆盖核心自带的版本，反而导致编译报错（`camera_config_t has no member named pin_sccb_sda`）。
> 正确顺序：先不装，直接编译 `04_camera`；**只有报 `esp_camera.h: No such file or directory` 时**再去库管理器装最新版。

> 装完在 `File` → `Examples` 里能看到这些库的示例，就说明装成功了。
> **不要装** `ESP32-audioI2S` 的老 2.x 版本（只支持 core 2.x），装的时候看清版本号。

## 4. 配置 TFT_eSPI（屏幕专用，唯一需要"改库文件"的地方）

TFT_eSPI 是个"编译期配置"的库，必须替换它的配置文件：

1. 找到库目录：`我的文档\Arduino\libraries\TFT_eSPI\`
2. 里面有个 `User_Setup.h`（还有个 `User_Setup_Select.h`）
3. **把原文件改名备份**成 `User_Setup.h.bak`
4. 把我们项目里的 [`config/User_Setup.h`](../config/User_Setup.h) **复制过去覆盖**

> 这个文件里已经写好了你这块板的所有引脚（SCL=21、SDA=47、CS=3、DC=38），**不用改任何东西**。
> 如果屏幕花屏，打开它把 `SPI_FREQUENCY` 从 40000000 改成 27000000。

## 5. 开发板设置（★ 每一项都不能错）

插上 **UART 口**（丝印 `UART` / `COM`，不是 `USB` 那个）的 Type-C 线，然后 `Tools` 菜单里逐项设置：

| 菜单项 | 必须选 |
|---|---|
| **Board** | `ESP32S3 Dev Module` |
| **USB CDC On Boot** | **Disabled** ← 最容易错的一项 |
| **CPU Frequency** | `240MHz (WiFi)` |
| **Flash Mode** | `QIO 80MHz` |
| **Flash Size** | `16MB (128Mb)` |
| **Partition Scheme** | `16M Flash (2MB APP/12.5MB SPIFFS)` ← 见下方说明 |
| **PSRAM** | **`OPI PSRAM`** ← 第二个最容易错的一项 |
| **Upload Speed** | `921600` |
| **Port** | 选带 `COM` 的那个（通常 COM3~COM8） |

**为什么这两项最容易错：**

- `USB CDC On Boot` 如果选 Enabled，串口监视器会去抢原生 USB 口，而那两个引脚（GPIO19/20）被超声波占用了 → 你会看到**满屏乱码或者啥都没有**。
- `PSRAM` 如果选 Disabled，摄像头和录音都会申请内存失败 → 报 `cam_hal: Failed to allocate`。

**关于 Partition Scheme 为什么选 SPIFFS 那一项：**

第 8 步的总控程序里，**后端 2（硅基流动）的语音合成**要把云端返回的 mp3 先存进板子的文件系统再播放。SPIFFS 分区只有在 `.../SPIFFS` 这类方案里才有；如果选 `FATFS` 方案，那段代码会直接报"SPIFFS 挂载失败"。

- 用**后端 1（百度，默认）**：分区选哪个都能跑；
- 用**后端 2（硅基流动）**：必须是 `16M Flash (2MB APP/12.5MB SPIFFS)`；
- 万一 2MB 的 APP 空间装不下（编译报 `text section exceeds available space`），改回 `Huge APP (3MB No OTA/1MB SPIFFS)` —— 它也有 SPIFFS，只是小一点。

## 6. 烧录 + 看串口

1. `File` → `Open`，打开 `firmware\01_display` 这个**文件夹**里的 `01_display.ino`
2. 点左上角 **→** 按钮（Upload）
3. 看到 `Hard resetting via RTS pin...` 就成功了
4. 点右上角**放大镜**图标打开串口监视器，右下角波特率选 **115200**

> 上传失败、报 `Failed to connect to ESP32-S3` 时：
> 按住板上的 **BOOT** 键 → 点上传 → 看到 `Connecting...` 时松开 BOOT。这招能解决 90% 的上传失败。

```
├─ README.md                  ← 从这里开始
├─ docs\
│  ├─ 01_接线总表.md           ← 施工图（接线只看这份）
│  ├─ 02_环境搭建.md           ← 本文件
│  ├─ 03_分步测试指南.md       ← 8 步调试路线

├─ config\User_Setup.h         ← 覆盖到 TFT_eSPI 库目录
├─ firmware\
│  ├─ _shared\pinmap.h         ← 引脚唯一权威来源（不要单独改各目录的副本）
│  ├─ 01_display\              ← 屏幕测试
│  ├─ 02_motor\                ← 电机测试
│  ├─ 03_servo\                ← 云台测试
│  ├─ 04_camera\               ← 图传测试
│  ├─ 05_audio\                ← 音频测试
│  ├─ 06_sonar\                ← 超声波测试
│  └─ 07_main\                 ← 总控（最后烧这个）
└─ tools\
   ├─ sync_pinmap.ps1          ← 把 pinmap.h 同步到所有 sketch
   └─ check_pins.ps1           ← 体检：查写死引脚/禁区引脚
```

**改引脚的规则**：只改 `firmware\_shared\pinmap.h`，然后在项目根目录运行

```powershell
cd D:\Users\THUCJX\Desktop\Code\Project\AI-Robot
powershell -ExecutionPolicy Bypass -File tools\sync_pinmap.ps1
powershell -ExecutionPolicy Bypass -File tools\check_pins.ps1
```

第二条是"代码体检"，输出 `ALL CHECKS PASSED` 才算没问题（脚本是纯英文输出，避免 Windows 终端乱码）。

**绝对不要**手动去改 `firmware\01_display\pinmap.h` 这样的副本——下次同步就被覆盖了。
